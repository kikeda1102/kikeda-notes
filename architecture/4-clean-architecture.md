# クリーンアーキテクチャ

クリーンアーキテクチャとは

ソフトウェアを関心事に応じて複数の層状に隔離して記述することで保守性、拡張性の高い構造を保つ設計原則。

## 背景

Robert C. Martin (Uncle Bob)により 2012 年に提唱。
ポート & アダプター、
オニオンアーキテクチャがあった
それをより発展させたもの

## 構成要素
ビジネスロジックを最も内側に置き、
インターフェースを外側に置く
依存の向きは常に外側から内側となるようにする

### ドメイン層
もっとも基本的なビジネスロジックを記述する

### Use Cases 層
ビジネスロジックの適用のしかたを記述する

### Controllers 層 / Interface Adapters 層
インターフェースのadapterとなるロジックを記述する

### Infrastructure 層
DB, UI, デバイス、フレームワークなどdriverを記述する

## 依存性の向き
外側が内側に依存し、内側は外側に依存しないようにする
依存性逆転の原則 (cf. SOLID原則 ) に従って実装する
ドメインではインターフェースを実装する (Port)
Infrastructure が ドメインで定義されたインターフェースの実装を担う (Adapter)

## Layered アーキテクチャとの比較
依存性の向きが異なる
Layered は プレゼンテーション層→ビジネスロジック層→データアクセス層 と、ビジネスロジックがDBの詳細に依存。
